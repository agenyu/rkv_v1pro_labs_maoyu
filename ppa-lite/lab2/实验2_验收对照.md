## 必做1 合法包完整处理

**结果寄存器（10 分）**：`lab2_valid_test` 跑 4 种长度 × 4 种合法类型，每包都由
`run_packet_m3` 比对 4 个结果：

```systemverilog
check(m3vif.res_pkt_len_o  === pkt.pkt_len,          "M3 RES_PKT_LEN mismatch");
check(m3vif.res_pkt_type_o === pkt.pkt_type,         "M3 RES_PKT_TYPE mismatch");
check(m3vif.res_payload_sum_o === pkt.payload_sum(), "M3 payload sum mismatch");
check(m3vif.res_payload_xor_o === pkt.payload_xor(), "M3 payload xor mismatch");
```

RTL 侧 `res_pkt_len_o/res_pkt_type_o` 直接来自 `pkt_len_r/pkt_type_r`（51-56 行），
这两个寄存器只在首字解析时写入（166-168 行），之后整个包处理期间不变。

**FSM 波形（5 分）**：`wave/ppa_wave_m3.do` 第 3 组把 `state` 按符号名显示，
三个值分别是 `S_IDLE / S_PROCESS / S_DONE`（25-29 行）。演示时指出转移顺序：

- `start_i && !busy_r` 的下一拍进入 `S_PROCESS`（119-120 行）；
- 每读一个字在 `S_PROCESS` 停留，`issue_read_r`/`wait_read_r` 交替（148-152 行）；
- 读到最后一个字直接跳 `S_DONE`（196-201 或 208-213 行），`S_DONE` 里保持 `done=1`（223-228 行）。

## 必做2 长度越界检测

```systemverilog
pkt = new(); pkt.build(3, 8'h01, 0);    run_packet_m3(...);   // 下溢，搜 [评分 2-必做2.1]
pkt = new(); pkt.build(33, 8'h01, 0);   run_packet_m3(...);   // 上溢，搜 [评分 2-必做2.2]
```

RTL 判定只有一行（170-172）：

```systemverilog
le_v = (len < 8'd4) || (len > 8'd32) || ((exp_len_r != 6'd0) && (len != exp_len_r));
```

三个条件或在一起：下界、上界、与期望长度不符。len=3 命中第一个，len=33 命中第二个。

**done 仍然拉高**：这是越界检测的关键——报错不等于挂死。`words_for_len()`（64-74 行）
对 len=3 返回 1 个字、len=33 返回 8 个字，两种情况都能正常走完并置 `done_o`，
`run_packet_m3` 里等 done 并检查 busy 已落的那几行，搜 `[评分 2-必做2.3]`。

## 必做3 busy/done 时序

**第 1 拍 busy（10 分）**：`lab2_valid_test` 末尾重新启动一次，专门测这个
（搜 `[评分 2-必做3.1]`）：

```systemverilog
@(negedge m3vif.clk);
m3vif.start_i = 1'b1;        // 在 negedge 摆好 start
@(posedge m3vif.clk);        // 这个 posedge 采样 start_i
#1;
check(m3vif.busy_o === 1'b1, "busy_o not asserted on the first cycle after start_i");
```

RTL 在同一个 `always_ff` 里 `busy_r <= 1'b1`（132 行），所以采样 start 的那一拍
busy 就有效，中间没有额外延迟。**这是 10 分项，答辩时重点强调"零延迟响应"**。

**done 保持与清零（5 分）**，搜 `[评分 2-必做3.2]`：

```systemverilog
repeat (3) @(posedge m3vif.clk);
check(m3vif.done_o === 1'b1, "done_o did not hold while in DONE");   // 连续 3 拍仍为 1
check(m3vif.busy_o === 1'b0, "busy_o not low while in DONE");
...
check(m3vif.done_o === 1'b0, "done_o not cleared by re-start");      // 再次 start 同拍清 0
```

`S_DONE` 分支（223-228 行）每拍都把 `done_r <= 1'b1`，所以是**电平保持**不是脉冲；
再次 start 时走 119-133 行的启动分支，`done_r <= 1'b0`，同拍清掉。

## 选做4 type 合法性 + type_mask

```systemverilog
pkt.build(12, 8'h03, 1);   // 0x03 不是 one-hot，任何 mask 都非法   搜 [评分 2-选做4.1]
pkt.build(12, 8'h01, 1);   // 0x01 合法，但 mask=4'b1110 把 bit0 关了  搜 [评分 2-选做4.2]
```

RTL 的 `type_is_legal()`（85-96 行）只认 `0x01/0x02/0x04/0x08` 四种 one-hot 值，
分别对应 `type_mask[0..3]`；其它值一律 `default: return 1'b0`。

所以 0x03 走 default 直接非法；0x01 走 `type_mask[0]`，掩码关掉 bit0 后就返回假。
这两条正好覆盖"非法值"和"合法值被掩码屏蔽"两种不同路径。

## 选做5 hdr_chk 校验

```systemverilog
pkt.build(16, 8'h04, 1); pkt.force_bad_checksum(); run_packet_m3(pkt, 1'b1, ...); // algo=1 → 报错
pkt.build(16, 8'h04, 1); pkt.force_bad_checksum(); run_packet_m3(pkt, 1'b0, ...); // algo=0 → 不校验
```

同一个坏包、只改 `algo_mode`，这是最干净的对照实验。RTL 174-176：

```systemverilog
ce_v = algo_mode_r && (mem_rd_data_i[31:24] !=
       (mem_rd_data_i[7:0] ^ mem_rd_data_i[15:8] ^ mem_rd_data_i[23:16]));
```

`algo_mode_r` 与在表达式最前面，为 0 时整体短路为 0，所以旁路模式不报校验错。

**payload sum/XOR（5 分）**：从第 2 个字开始累加（183-193 行），参考模型
`payload_sum()/payload_xor()` 从 `bytes[4]` 开始算（搜 `[评分 2-选做5.3]` 附近，
在 `packet_item` 类里），两边独立实现、结果比对。首字 4 字节是包头，不进 payload。

## 演示命令

```powershell
cd C:\rkv_v1pro_labs\ppa-lite

make lab2          # lab2_valid_test + lab2_errors_test，日志在 lab2/logs/
make wave2         # 生成两个 wlf 到 lab2/wave_ppa/

vsim -view lab2/wave_ppa/lab2_errors_test.wlf -do wave/ppa_wave_m3.do
```

`vsim -view` 会占住终端直到窗口关闭，两条不能连着敲。双击工程根目录的
`打开实验2波形.bat` 可以一次弹出两个窗口。

波形上按顺序指四处：`start_i` → `busy_o`（同拍起）→ `state` 从 IDLE 进 PROCESS →
最后一字读完 `done_o` 起且 `busy_o` 落 → 结果寄存器稳定。
