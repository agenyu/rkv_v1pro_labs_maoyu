## 1 必做1 APB 读写时序

### 1.1 CTRL/CFG/STATUS 默认值（10 分）

代码位置：`lab1_defaults_test.run()`，搜 `[评分 1-必做1.1]`。

```systemverilog
lab1_apb_read(12'h000, data, 0); check(data === 32'h0000_0000, "CTRL reset");
lab1_apb_read(12'h004, data, 0); check(data === 32'h0000_00F1, "CFG reset");
lab1_apb_read(12'h008, data, 0); check(data === 32'h0000_0000, "STATUS reset");
// 紧接着 IRQ_EN / IRQ_STA / PKT_LEN_EXP / ERR_FLAG 也都查了复位值 0
```

被验实现是 `rtl/apb_slave_if.sv:156-167` 的复位分支：`ctrl_enable_r<=0`、
`cfg_algo_mode_r<=1`、`cfg_type_mask_r<=4'hF`。

**CFG 的 0xF1 在 RTL 里搜不到字面量**，它是第 141 行拼出来的：
`{24'b0, cfg_type_mask_r, 3'b0, cfg_algo_mode_r}` —— bit0 是 algo_mode=1、
bit7:4 是 type_mask=F，合起来正好 0xF1。被问到时按这个解释。

### 1.2 APB 两段式时序（5 分，波形抽查）

驱动在两个 task 里，搜 `[评分 1-必做1.2]`（`lab1_apb_write` / `lab1_apb_read`）：

```systemverilog
// SETUP 相位
@(negedge PCLK); PSEL=1; PENABLE=0; PWRITE/PADDR/PWDATA 摆好
// ACCESS 相位
@(negedge PCLK); PENABLE=1
// 采样点，避开竞争
@(posedge PCLK); #1; check(PREADY===1); check(PSLVERR===exp_err)
// 收尾
@(negedge PCLK); PSEL=0; PENABLE=0
```

RTL 侧对应：`access = PSEL && PENABLE`（70 行），`PREADY` 恒 1（77 行），
PKT_MEM 的读使能在 SETUP 相位就给出（82 行 `PSEL && !PENABLE`）。

演示时把波形游标停在任意一次传输上，指出：**PSEL 先拉高、PENABLE 晚一个周期**，
两者同时为 1 的那个周期才是 ACCESS，此时 PREADY=1、读数据在 PRDATA 上。

### 1.3 验收质量：PRDATA 写入位置（5 分）

标准答法：**PRDATA 没有"写入"这回事，它是纯组合输出。**

- 写发生在时序块 `always_ff`（156-206 行）：`write_access && PADDR==ADDR_xxx`
  时把 `PWDATA` 打进 `*_r` 寄存器，比如 173-175 写 CTRL、176-179 写 CFG。
- 读发生在组合块 `always_comb`（133-154 行）：按 PADDR 用 case 把寄存器或
  输入信号拼到 `PRDATA`，PKT_MEM 窗口则直连 `pkt_mem_rdata_i`。

一句话：**写路径进寄存器，读路径是 case 直通，PRDATA 本身不存值**。这也顺带
解释了为什么给 STATUS 写值不生效——它不在 `writable_csr`（101-108 行）里。

## 2 必做2 PKT_MEM 写入映射

### 2.1 8 个 word 全部正确（10 分）

代码位置：`lab1_pkt_mem_test`，搜 `[评分 1-必做2.1]`。

```systemverilog
for i in 0..7: apb_write(0x040 + i*4, 0xA5000000 + i)
for i in 0..7: apb_read (0x040 + i*4) 并 check 回读值
```

`0xA5000000+i` 这个模式是刻意的：高 24 位不变、低字节递增，波形上一眼能看出
addr 和 data 是否一一对应。

RTL 侧：窗口判断 72 行（`0x040 <= PADDR <= 0x05C`），写使能 81 行
（`write_access && pkt_mem_window && !busy_i`），地址 79 行，数据 80 行直通 `PWDATA`。

波形看 `lab1/wave_ppa/lab1_pkt_mem_test.wlf` 第 4 组（**这个用例走的是主通路
`dut`，要用 `wave/ppa_wave.do` 打开**）：`pkt_mem_we_o` 拉高的那 8 个周期里，
`pkt_mem_addr_o` 从 0 递增到 7，`pkt_mem_wdata_o` 从 `0xA5000000` 递增到
`0xA5000007`，`u_m2/mem[0..7]` 依次变成对应的值。

实测抽查（`run 360 ns` 处）：`addr=7`、`wdata=0xA5000007`、`mem(0)=0xA5000000`，
与用例写入的顺序一致。

### 2.2 地址计算（5 分）

```systemverilog
assign pkt_mem_addr_o = PADDR[5:2];     // rtl/apb_slave_if.sv:79
```

推导：`0x040 = 12'b0100_0000`，取 `[5:2]` 四位得 `4'b0000`，截到 3 bit 就是 0；
`0x044 → 1`，`…`，`0x05C → 7`。

等价写法 `(PADDR - 0x040) >> 2`，但 RTL 用的是位选，因为 0x040 的低 6 位全 0，
减法和移位都被综合器优化成同一根线。**要点：地址按字（word）寻址，字节地址右移 2 位**。

### 2.3 验收质量（5 分）

能说清三件事即可：窗口边界 0x040~0x05C（8 个字）、`we` 的三个与项
（PSEL&&PENABLE&&PWRITE / 在窗口内 / 不 busy）、`wdata` 直通不寄存。

## 3 必做3 RES_* 读通路

### 3.1 4 个寄存器全部正确（10 分）

代码位置：`lab1_defaults_test` 中段，搜 `[评分 1-必做3.1]`。

```systemverilog
m1vif.res_pkt_len_stub=6'h2A; res_pkt_type_stub=8'hA5;
m1vif.res_payload_sum_stub=8'h3C; res_payload_xor_stub=8'h96; pkt_mem_rdata_stub=32'hC0012345
APB 读 0x018/0x01C/0x020/0x024/0x040 分别比对
```

桩值故意选了互不相同、且和地址不对应的数（2A/A5/3C/96），避免"读错地址也碰巧对"。

RTL 侧 146-149 行：`ADDR_RES_LEN → {26'b0, res_pkt_len_i}` 等，四个 RES 寄存器
都是组合直通输入端口。端口在 `tb/tb.sv:62-65` 接到 `m1_apb.*_stub`。

### 3.2 地址译码完整（5 分）

译码由三个函数/信号拼成，覆盖 0x000~0xFFF 全空间：

- `readable_csr()`（92-99 行）：11 个可读 CSR（0x000/004/008/00C/010/014/018/01C/020/024/028）。
- `writable_csr()`（101-108 行）：5 个可写（CTRL/CFG/IRQ_EN/IRQ_STA/PKT_LEN_EXP）。
- `pkt_mem_window`（72 行）：0x040~0x05C。
- 剩下的 0x02C~0x03C、0x060~0xFFC 全部落到 default，读走 127-129 行、写走
  118-121 行，统一给 PSLVERR。

`lab4_code_cov_test`（搜 `[评分 1-必做3.2]`）专门扫这些边角：非对齐地址
0x001/0x002/0x003、未映射 0x080~0xFFC、PKT_MEM 边界 0x03C/0x060。

### 3.3 验收质量（5 分）

口述分三区：**CSR 区 0x000-0x028（按 4 字节对齐，共 11 个）、PKT_MEM 区
0x040-0x05C（8 个字）、其余非法**。非对齐地址不单独报错，会按位比较落到 default。

## 4 选做4 PSLVERR

### 4.1 写 RO → PSLVERR=1 且值不变（10 分）

代码位置：`lab1_pslverr_test`，搜 `[评分 1-选做4.1]`。

```systemverilog
lab1_apb_write(0x008, 0xFFFFFFFF, 1);   // STATUS 只读，期望 PSLVERR=1
lab1_apb_write(0x018, 0xFFFFFFFF, 1);   // RES_LEN 只读
lab1_apb_write(0x02C, 0xFFFFFFFF, 1);   // 未映射
lab1_apb_read (0x02C, data, 1);         // 未映射地址读也报错
// 回读 STATUS(0x008) 和 RES_LEN(0x018)，必须是原值 0
```

第三个参数 `exp_err` 就是期望的 PSLVERR，`lab1_apb_write/read` 内部会 check
（搜 `[评分 1-必做1.2]` 能看到那两行 check）。

RTL 侧 118-121 行：`!writable_csr(PADDR)` → `PSLVERR=1`。写被拒后没有任何寄存器
更新语句被执行，所以值自然不变——那两行回读就是这条的直接证据。

### 4.2 未定义地址 → PSLVERR（5 分）

同一个用例里（搜 `[评分 1-选做4.2]`），写和读 0x02C 各一次。RTL 读侧在 127-129
行（`!readable_csr`），写侧在 118-121 行。

### 4.3 验收质量（5 分）

PSLVERR 一共四个来源，全在 110-131 行的组合块里：

1. 写不可写 CSR（118-121）
2. 读不可读 CSR（127-129）
3. PKT_MEM 在 busy 时写（113-116）
4. CTRL 写 start 位但 enable 没开（122-124）

## 5 选做5 IRQ 完整实现

### 5.1 IRQ_EN 读写 / IRQ_STA RW1C（10 分）

RTL：

- EN 写入：180-183 行，bit0=done、bit1=err。
- STA 置位：188-195 行，`done_i` 上升沿且对应 EN=1 时置 1。
- STA 清除：197-204 行，写 1 清 0、写 0 不动（RW1C）。

TB：`lab3_irq_test`（搜 `[评分 1-选做5.1]`）分四步验，每步都回读寄存器：

1. `IRQ_EN` 写 `2'b11` 读回 `2'b11`、写 `2'b00` 读回 `2'b00` —— 证明它是普通可读写寄存器。
2. 两位都打开后跑一个坏包（`force_bad_checksum()`），一个包同时满足 done 与 error，
   两位 STA 在同一拍一起置起，`0x010` 读回 `2'b11`。
3. 写 `0x010 = 1` 只清 done：`done_irq_sta_r` 落 0，`err_irq_sta_r` 必须**保持 1**
   （这就是"写 0 保持"），`irq_o` 因为还有 err 挂着也**不掉**。再写 `0x010 = 2`，
   err 才落，`irq_o` 同拍落 0 —— 证明两位独立、`irq_o` 是两位的或。
4. 把 `IRQ_EN` 改成 `2'b10`（关掉 done_en）再跑同样的坏包，done 照样发生但
   `done_irq_sta_r` 保持 0 —— 证明 EN 只门控置位，不参与 `irq_o`。

只写"写 1 清 0"是不够的：RW1C 的另一半是"写 0 不动"，只有一次写里同时存在
"该清的位"和"该保持的位"，这条行为才被真正验证到。

### 5.2 irq_o 时序（5 分）

```systemverilog
assign irq_o = done_irq_sta_r || err_irq_sta_r;    // rtl/apb_slave_if.sv:90
```

注意评分表写的是 `irq_o = done_irq | err_irq`，实现里或的是 **STA 位，不是 EN 位**
——EN 只门控 STA 能不能被置起来。被追问时这点要答对：EN 是"允许中断"，STA 是
"中断发生了什么"，irq_o 反映的是 STA，所以是电平信号，不清就一直高。

波形看 `lab3/wave_ppa/lab3_irq_test.wlf` 第 5 组：`done_i` 上升 → 下一拍
`done_irq_sta_r` 和 `err_irq_sta_r` 一起置 1 → `irq_o` 同时变高。之后写
`0x010 = 1`，波形上只有 `done_irq_sta_r` 一根线掉下去，`err_irq_sta_r` 原地不动、
`irq_o` 也还高着；再写 `0x010 = 2`，`err_irq_sta_r` 才落，`irq_o` 跟着同拍落 0。

### 5.3 验收质量（5 分）

说清 RW1C 的"写 1 清、写 0 保持"，以及 irq_o 是 STA 的或、不是脉冲。

```powershell
vsim -view lab3/wave_ppa/lab3_irq_test.wlf      -do wave/ppa_wave.do        # 看 dut（IRQ / FSM）
```

`vsim -view` 是前台进程，窗口不关终端就被占着，所以这几条不能连着敲。
要么双击工程根目录的 `打开实验1波形.bat`（一次弹出 3 个窗口，`lab3_irq_test`
那条单独开），要么开多个终端，或者在已打开的 vsim 里 `File -> Open` 选下一个 wlf。

层次对应关系：

- `lab1_defaults_test`、`lab1_pslverr_test` 用 `lab1_apb_read/write` 驱动 `m1vif`，
  即 `tb` 里单独例化的 `u_lab1_m1` → 用 `ppa_wave_lab1.do`。
- `lab1_pkt_mem_test` 用的是 `apb_write/apb_read`（主通路 `apb`，即 `ppa_top`），
  所以 PKT_MEM 的 8 次写出现在 `dut/u_m1` 上，数据落在 `dut/u_m2/mem` → 用 `ppa_wave.do`。
- `lab3_irq_test` 走主通路 → `ppa_wave.do`。

**混用会看到一片空白或者全 0**，验收时如果对方说"你这波形不对"，先确认脚本有没有用错。
