# PPA-Lite 仿真方式（命令手册）

本文是 PPA-Lite 工程的完整仿真操作手册，所有命令都在
`C:\rkv_v1pro_labs\ppa-lite` 下执行，已实操验证。

## 1 环境要求

| 项 | 要求 | 自检命令 |
|---|---|---|
| 仿真器 | QuestaSim 2021.1（`vlog` / `vsim` / `vcover` 在 `PATH` 中） | `vlog -version` |
| 编译驱动 | GNU Make 4.x | `make -v` |
| Shell | MSYS2 `sh.exe`（Makefile 里的 `for` 循环依赖它） | `where sh` |
| 许可 | `LM_LICENSE_FILE` 指向有效 license | `echo $LM_LICENSE_FILE` |

PowerShell 里看不到 `LM_LICENSE_FILE` 时，临时补一句：

```powershell
$env:LM_LICENSE_FILE = "D:\BaiduNetdiskDownload\Crack\mgcld.lic"
```

## 2 路径要求（必须遵守）

**编译库目录必须是纯 ASCII 路径。**

`vlog -work ./work` 会在 `work/` 下建一个 sqlite 数据库 `_lib.qdb`。
路径里含中文时 sqlite 建不了文件，`vlib` 只留下一个只有 `_info` 的空壳，
之后每次 `vlog` 都会死在这一步：

```text
init_dbInfo() DATABASE ERROR: (sqlite3_open .../work/_lib.qdb): unable to open database file
mtiLibWrite(): INTERNAL ERROR: Unexpected null object encountered
** Fatal: (vlog-9) Problem while writing internal ...
```

源码本身放在中文路径下不影响编译，卡住的只有 `-work` 指向的库目录。
本工程现在就在纯英文路径 `C:\rkv_v1pro_labs\ppa-lite`，可直接运行。

如果 `work/` 已经是个半成品（只有 `_info`、没有 `_lib.qdb`），
Makefile 的 `comp` 会因为它存在而跳过 `vlib`，然后继续编译失败。
此时先删掉 `work/` 再重来：

```powershell
Remove-Item -Recurse -Force .\work
make comp
```

## 3 编译

```powershell
make comp
```

内部展开为两步，顺序不能反（TB 要 import package、要例化 RTL 模块）：

```text
vlog -work ./work -sv -timescale=1ns/1ps -cover sbceft -coverfec -fsmverbose=b -l comp_dut.log ./rtl/*.sv
vlog -work ./work -sv -timescale=1ns/1ps -l comp_tb.log ./tb/*.sv
```

只编 RTL、不编 TB（排查 RTL 语法错误时用）：

```powershell
vlog -work ./work -sv -timescale=1ns/1ps -cover sbceft -coverfec -fsmverbose=b ./rtl/apb_slave_if.sv ./rtl/packet_sram.sv ./rtl/packet_proc_core.sv ./rtl/ppa_top.sv
```

期望结果：`comp_dut.log` 和 `comp_tb.log` 里都是 `Errors: 0, Warnings: 0`。

## 4 跑单个用例

```powershell
make run TESTNAME=lab3_e2e_test SEED=7
```

- `TESTNAME` 默认 `lab1_defaults_test`，`SEED` 默认 `1`。
- 日志文件名固定为 `run_<TESTNAME>_<SEED>.log`，覆盖率存到
  `cov/runs/<TESTNAME>_<SEED>.ucdb`。
- `make run` 会先自动 `comp`，所以改完源码直接 run 即可。

等价的手工命令（不经 make，便于加 `-gui` 或换 `-do`）：

```powershell
vsim -c -voptargs=+acc -work ./work tb -sv_seed 7 `
     -coverage -assertdebug -assertcounts `
     +TESTNAME=lab3_e2e_test +TEST_SEED=7 `
     -do "coverage save -onexit cov/runs/lab3_e2e_test_7.ucdb; run -all; quit -f"
```

想看图形界面：把 `-c` 去掉，把 `-do` 里的内容手动敲进 Transcript。

## 5 冒烟

```powershell
make smoke
```

编译后跑 `lab1_defaults_test` + `lab3_e2e_test`，约 30 秒。
两条用例都必须出现：

```text
[TEST START] lab1_defaults_test seed=1
[TEST PASS] lab1_defaults_test
Errors: 0, Warnings: 0
```

## 6 按实验分组回归

```powershell
make lab1      # lab1_defaults / lab1_pkt_mem / lab1_pslverr
make lab2      # lab2_valid / lab2_errors
make lab3      # e2e / two_frames / busy_protect / irq / reset_recovery
make lab4      # random / error_mix / closure / code_cov
```

每组内部按 `SEED`（默认 1）跑一遍，任一用例未打印 `[TEST PASS]`
或工具统计非 0，make 立刻以非 0 退出。

## 7 正式全回归

```powershell
make regress SEEDS="1 2 3"
```

- 14 个用例 × 3 个 seed = **42 次仿真**
- 每次都会保存 `cov/runs/<test>_<seed>.ucdb`
- 日志为根目录下的 `run_<test>_<seed>.log`
- 判定标准三条同时成立：`[TEST START] <test> seed=<n>`、
  `[TEST PASS] <test>`、`Errors: 0, Warnings: 0`

跑完自查：

```powershell
(Select-String -Path regress.log -Pattern "TEST PASS").Count    # 应为 42
(Select-String -Path regress.log -Pattern "TEST FAIL").Count    # 应为 0
```

`make cov` 等价于 `make regress`（覆盖率在每次仿真时随 `coverage save` 落盘）。

## 8 覆盖率合并与报告

```powershell
make report
```

这一步会自动依次完成 `mergecov`、`filtercov` 和报告生成，展开为：

```text
vcover merge -out cov/merged.ucdb cov/runs/*.ucdb
vcover merge -out cov/dut_merged.ucdb -instance /tb/dut -recursive cov/merged.ucdb
vsim -c -viewcov cov/dut_merged.ucdb -do "do cov_exclude.do; quit -f"
vcover report -html -output cov/html_dut -details cov/dut_filtered.ucdb
vcover report -html -output cov/html_functional -details cov/merged.ucdb
vcover report -details cov/dut_merged.ucdb   > cov/dut_merged.txt      # 原始
vcover report -details cov/dut_filtered.ucdb > cov/dut_filtered.txt    # 过滤后
vcover report -cvg  -details cov/merged.ucdb   > cov/functional.txt
vcover report -summary cov/dut_filtered.ucdb   > cov/dut_summary.txt
vcover report -summary cov/merged.ucdb         > cov/full_summary.txt
```

`filtercov` 单独跑（只做过滤，不出报告）：

```powershell
make filtercov
```

它执行 `cov_exclude.do`，把登记在 `coverage_filter_register.csv` 里的不可达项排除，
结果写到 `cov/dut_filtered.ucdb`。**原始库 `dut_merged.ucdb` 不会被改动**，
所以过滤前后的数字都能拿出来对照：

| 指标 | 原始 | 过滤后 |
|---|---|---|
| Branch | 98.05% | 100.00% |
| Condition | 96.42% | 100.00% |
| Statement | 96.93% | 100.00% |
| Toggle | 99.69% | 100.00% |
| Expression / FSM | 100% | 100.00% |
| 综合 | 98.73% | 100.00% |

只想合并、先不生成 HTML：

```powershell
make mergecov
```

只看某一类覆盖率（不用重新合并）：

```powershell
vcover report -summary  cov/dut_merged.ucdb
vcover report -summary  cov/dut_filtered.ucdb
vcover report -assert   cov/merged.ucdb
vcover report -cvg      cov/merged.ucdb
vcover report -details  cov/dut_filtered.ucdb | Select-String "\*\*\*0\*\*\*"   # 找未命中项
vcover report -details  -showexcluded cov/dut_filtered.ucdb                     # 看被排除的项
```

## 10 波形（验收抽查用）

`-c` 批处理模式下只加 `-wlf` 是不记数据的，必须先 `log -r` 把层次登记成记录对象，否则 wlf 打开后一片空白。

单个用例出波形：

```powershell
make wave TESTNAME=lab1_pkt_mem_test
# 生成 lab1/wave_ppa/lab1_pkt_mem_test.wlf
#     日志 lab1/logs/run_wave_lab1_pkt_mem_test.log
```

四个实验各有一条批量生成命令，产物按用例名前缀自动落到对应实验目录：

```powershell
make wave1   # lab1/wave_ppa/ 三个，另加 lab3/wave_ppa/lab3_irq_test.wlf
make wave2   # lab2/wave_ppa/ 两个
make wave3   # lab3/wave_ppa/ 五个
make wave4   # lab4/wave_ppa/ 四个
```

| 目标 | 用例 | 落点 |
|---|---|---|
| `make wave1` | `lab1_defaults_test`、`lab1_pkt_mem_test`、`lab1_pslverr_test`、`lab3_irq_test` | lab1 ×3 + lab3 ×1 |
| `make wave2` | `lab2_valid_test`、`lab2_errors_test` | lab2 ×2 |
| `make wave3` | `lab3_e2e_test`、`lab3_two_frames_test`、`lab3_busy_protect_test`、`lab3_irq_test`、`lab3_reset_recovery_test` | lab3 ×5 |
| `make wave4` | `lab4_random_test`、`lab4_error_mix_test`、`lab4_closure_test`、`lab4_code_cov_test` | lab4 ×4 |

注意 `wave1` 里的 `lab3_irq_test` 是实验1 选做5 借用的用例，它按自己的名字前缀落到
`lab3/wave_ppa/`，不在 lab1 下。

打开波形并加载信号分组（每个实验一组，逐条可复制）。

先说明为什么这些命令**不能连着敲**：`vsim -view` 是前台进程，GUI 窗口不关，
终端就一直被它占着，第二条命令要么排队要么直接被忽略，看起来就像"只能执行一条"。
有两种绕法：

**做法一（推荐）：双击批处理，一个实验的所有窗口一次弹出来**

```text
打开实验1波形.bat      3 个窗口  ppa_wave_lab1.do ×2 + ppa_wave.do ×1
打开实验2波形.bat      2 个窗口  ppa_wave_m3.do
打开实验3波形.bat      5 个窗口  ppa_wave.do
打开实验4波形.bat      4 个窗口  ppa_wave.do
```

脚本内部用的是 `start`（异步启动），所以三个 vsim 并行开，互不阻塞。脚本里有一条
前置检查：对应 `labN/wave_ppa/*.wlf` 不存在会提示先跑 `make waveN`，不会静默失败。

**做法二：开多个终端**

每个 PowerShell 窗口敲一条，各占一个进程。或者在已经打开的 vsim 里用
`File -> Open -> ...` 选中另一个 wlf，它就作为新的数据集出现在左侧 Objects 栏，
不用关掉当前窗口。

手动逐条打开的命令如下：

```powershell
# 实验1
vsim -view lab1/wave_ppa/lab1_defaults_test.wlf -do wave/ppa_wave_lab1.do
vsim -view lab1/wave_ppa/lab1_pslverr_test.wlf  -do wave/ppa_wave_lab1.do
vsim -view lab1/wave_ppa/lab1_pkt_mem_test.wlf  -do wave/ppa_wave.do
vsim -view lab3/wave_ppa/lab3_irq_test.wlf      -do wave/ppa_wave.do

# 实验2
vsim -view lab2/wave_ppa/lab2_valid_test.wlf    -do wave/ppa_wave_m3.do
vsim -view lab2/wave_ppa/lab2_errors_test.wlf   -do wave/ppa_wave_m3.do

# 实验3
vsim -view lab3/wave_ppa/lab3_e2e_test.wlf            -do wave/ppa_wave.do
vsim -view lab3/wave_ppa/lab3_two_frames_test.wlf     -do wave/ppa_wave.do
vsim -view lab3/wave_ppa/lab3_busy_protect_test.wlf   -do wave/ppa_wave.do
vsim -view lab3/wave_ppa/lab3_reset_recovery_test.wlf -do wave/ppa_wave.do
vsim -view lab3/wave_ppa/lab3_irq_test.wlf            -do wave/ppa_wave.do

# 实验4
vsim -view lab4/wave_ppa/lab4_random_test.wlf    -do wave/ppa_wave.do
vsim -view lab4/wave_ppa/lab4_error_mix_test.wlf -do wave/ppa_wave.do
vsim -view lab4/wave_ppa/lab4_closure_test.wlf   -do wave/ppa_wave.do
vsim -view lab4/wave_ppa/lab4_code_cov_test.wlf  -do wave/ppa_wave.do
```

实验4 的验收重点是覆盖率不是波形，但这四个 wlf 答辩追问实现细节时用得上，
比如被问"非法类型那一路信号怎么走的"就直接开 `lab4_error_mix_test.wlf`。

三套脚本对应三套层次，**不能混用**：

| 脚本 | 层次 | 用于 |
|---|---|---|
| `wave/ppa_wave_lab1.do` | `/tb/u_lab1_m1` + `/tb/m1_apb` | `lab1_defaults_test`、`lab1_pslverr_test`（走 `lab1_apb_*`，驱动独立的 M1 实例） |
| `wave/ppa_wave_m3.do` | `/tb/u_m3_standalone` + `/tb/m3` | 实验2 两个用例（不经 APB，直接驱动 standalone M3） |
| `wave/ppa_wave.do` | `/tb/dut`（`ppa_top`） | `lab1_pkt_mem_test`、实验3、实验4 全部（走主通路 `apb`） |

用错脚本的现象是信号全 0 或者直接报找不到对象。

`log` 里额外登记了两个数组，所以数据面能直接看：`dut/u_m2/mem`（PKT_MEM 8 个字的实时内容）和 `m3/mem_words`（实验2 的 8 个字模型）。

## 11 清理

```powershell
make clean
```

删除 `work/`、`cov/`、根目录 `*.log`、`*.wlf`、`*.ucdb`，并清掉各实验目录下的
`labN/logs/*.log` 和 `labN/wave_ppa/*.wlf`（不动 labN 里 MCDT 实验的 `work/`、`wave/`）。
**注意：`cov/` 会被一起删掉**，要保留覆盖率报告就别执行这一条。

只删编译库、保留覆盖率：

```powershell
Remove-Item -Recurse -Force .\work
```

## 12 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `sqlite3_open ... unable to open database file` | 工程在中文路径下 | 整体挪到纯英文路径 |
| `comp` 很顺利但 `vlog` 仍报同样的错 | `work/` 里是上次失败留下的空壳，`comp` 跳过了 `vlib` | 删掉 `work/` 重新 `make comp` |
| 换路径/换机器后 vsim 报莫名 `Errors: 2` | 编译库是从旧路径带过来的，里面有过期编译单元 | 删 `work/` 重编 |
| make 返回 0 但用例其实挂了 | `-do "...; quit -f"` 里的 `quit -f` 会强制把退出码改成 0 | 以日志里的 `[TEST PASS]` 和 `Errors: 0, Warnings: 0` 为准，Makefile 已内置 grep 校验 |
| `unknown test: xxx` | `+TESTNAME=` 拼错 | 对照第 12 节用例清单 |
| 波形窗口空白 | `vsim.exe` 直接启动时没有数据源也没有信号 | 用 `-wlf` + `log -r /*` 生成，再 `vsim -view` 打开 |
