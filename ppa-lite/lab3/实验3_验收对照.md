## 必做1 端到端链路

**读回一致（10 分）**：`lab3_e2e_test` 只做一件事——写 8 字节包、启动、等 done、
比对全部结果（搜 `[评分 3-必做1.1]`）：

```systemverilog
pkt.build(8, 8'h02, 0);            // len=8, type=0x02
run_packet_top(pkt, 1'b1, 4'hF, 6'd8);
```

`run_packet_top`（搜 `[评分 3-必做1.1/1.3]`）内部的六步就是完整链路：

```systemverilog
write_packet_to_apb(pkt);   // 8 个字写 0x040~0x05C
configure_top(...);         // CFG / PKT_LEN_EXP / CTRL.enable
start_top();                // CTRL.start=1
wait_top_done(done_ok);     // 轮询 STATUS.done
read_top_results(...);      // 读 STATUS / RES_* / ERR_FLAG 六个寄存器
check(res_len[5:0]  === pkt.pkt_len,  "RES_PKT_LEN mismatch");
check(res_type[7:0] === pkt.pkt_type, "RES_PKT_TYPE mismatch");
```

**M1→M3 信号连接（5 分，角色轮换提问）**：按数据流背一遍，连线和行号都在 `rtl/ppa_top.sv`：

1. **写包**：APB 写 0x040~0x05C → `u_m1` 的 `pkt_mem_we_o/addr_o/wdata_o`（`apb_slave_if.sv:79-81`）
   → `u_m2` 的 `apb_wr_en/apb_addr/apb_wr_data`（`ppa_top.sv:80-91`）。
2. **启动**：写 CTRL bit1 → `u_m1.start_o`（`apb_slave_if.sv:78`）→ `u_m3.start_i`（`ppa_top.sv:96`）。
3. **读包**：`u_m3.mem_rd_en_o/addr_o`（100-101 行）→ `u_m2.proc_rd_en/addr` →
   `proc_rd_data` → `u_m3.mem_rd_data_i`（102 行）。
4. **回状态**：`u_m3.done_o/busy_o`（103-104 行）→ `u_m1.done_i/busy_i` →
   `STATUS[1:0]`（`apb_slave_if.sv:142`）。
5. **回结果**：`u_m3.res_*`（105-108 行）→ `u_m1.res_*_i` →
   `RES_PKT_LEN/TYPE/SUM/XOR`（`apb_slave_if.sv:146-149`）。

一句话版本：**M1 是 APB 一侧的门房（CSR + PKT_MEM 窗口），M2 是 8×32 的存储，
M3 是唯一的处理器；M1 负责把包塞进 M2 并启动 M3，M3 读完 M2 后把结果和状态还给 M1。**

**波形同屏（5 分）**：`wave/ppa_wave.do` 已经同时挂了 APB 组（`PSEL/PENABLE/PADDR/PRDATA`）
和 FSM 组（`u_m3/state`、`busy_o`、`done_o`），打开 `lab3/wave_ppa/lab3_e2e_test.wlf`
一屏能看全，不用切换。

## 必做2 连续两帧

```systemverilog
pkt0.build(4,  8'h01, 0);   // 最小包，1 个字
pkt1.build(32, 8'h08, 1);   // 最大包，8 个字
run_packet_top(pkt0, 1'b1, 4'hF, 6'd4);
run_packet_top(pkt1, 1'b1, 4'hF, 6'd32);
```

两帧长度差 28 字节，`RES_PKT_LEN` 会从 4 变成 32，肉眼可辨；每次 `run_packet_top`
都按各自 `pkt.pkt_len` 校验，所以"各不相同且均正确"是逐帧验证的。
代码位置搜 `[评分 3-必做2.1]`。

**done 清零（5 分）**：第二帧启动走 `start_top()`（搜 `[评分 3-必做2.2]`），
里面已经有两行检查：

```systemverilog
check(vif.busy_o === 1'b1, "busy_o did not assert after accepted start");
check(vif.done_o === 1'b0, "done_o did not clear after accepted start");
```

波形上看 `done_o` 在第一帧结束后保持高，第二帧 start 的那一拍掉回 0，就是评分要的
"清零过程可见"。

## 必做3 STATUS 总线通路

STATUS 的位定义在 `apb_slave_if.sv:142`：

```systemverilog
ADDR_STATUS: PRDATA = {28'b0, format_ok_i, error_all, done_i, busy_i};
//                                          [3]      [2]     [1]     [0]
```

`STATUS[1:0]` 就是 `{done, busy}`，所以编码含义：

| busy | done | STATUS[1:0] | 含义 |
|---|---|---|---|
| 1 | 0 | `2'b01` | 处理中 |
| 0 | 1 | `2'b10` | 完成 |
| 0 | 0 | `2'b00` | 空闲 |

`lab3_busy_protect_test` 用 32 字节包把 busy 窗口拉长，然后在忙的时候读 STATUS
（搜 `[评分 3-必做3.1]`）：

```systemverilog
apb_write(12'h000, 32'h0000_0003, 0);   // enable + start
apb_read (12'h008, status, 0);
check(status[1:0] === 2'b01, "STATUS busy encoding mismatch");
wait_top_done(done_ok);
apb_read (12'h008, status, 0);
check(status[1:0] === 2'b10, "STATUS done encoding mismatch");   // 搜 [评分 3-必做3.2]
```

## 选做4 PSLVERR 保护（15 分）

```systemverilog
apb_read (12'h044, word_before, 0);          // 记下忙之前的值
apb_write(12'h044, 32'hDEAD_BEEF, 1);        // 忙时写，第三个参数 1 = 期望 PSLVERR=1
apb_read (12'h044, word_after, 0);
check(word_before === word_after, "PKT_MEM changed during busy write-protect test");
```

这是三项合一的检查：**PSLVERR 拉高**（由 `lab1_apb_write` 内部 check）+ **写入被丢弃**
（`DEAD_BEEF` 没进去）+ **原值不变**（前后读回相同）。代码搜 `[评分 3-选做4.1]`。

RTL 只有一处（`apb_slave_if.sv:113-116`）：

```systemverilog
if (pkt_mem_window) begin
  if (write_access) begin
    PSLVERR = busy_i;      // 忙的时候 PKT_MEM 写直接报错
  end
end
```

而真正写 SRAM 的使能是 `pkt_mem_we_o = write_access && pkt_mem_window && !busy_i`（81 行），
`busy_i` 与在最后，所以写脉冲根本不会产生——数据和 PSLVERR 是同一条件控制的，不会出现
"报了错但还是写进去了"。

## 选做5 中断路径闭环

**置位（10 分）**，搜 `[评分 3-选做5.1]`：

```systemverilog
apb_write(12'h00C, 32'h0000_0003, 0);   // IRQ_EN.done=1、err=1
apb_read (12'h00C, data, 0);
check(data[1:0] === 2'b11, "IRQ_EN readback: expect both enables set");

pkt.build(12, 8'h04, 1);  pkt.force_bad_checksum();   // 一个包同时满足 done 与 error
write_packet_to_apb(pkt);  configure_top(...);
...
apb_read (12'h010, data, 0);
check(data[1:0] === 2'b11, "both STA bits should be set by one error packet");
check(vif.irq_o === 1'b1, "irq_o did not assert with both STA bits set");
```

用坏包而不是正常包，是为了让两位 STA 在同一拍一起置起来——只有这样后面才验得了
"只清一位、另一位保持"。RTL 的置位条件在 188-195 行：`done_i` 上升沿
（`done_i && !done_d`）且对应 `_irq_en_r=1` 才置位。`irq_o` 是两位 STA 的或（90 行）。

**清零（5 分）**，搜 `[评分 3-选做5.2]`：

```systemverilog
apb_write(12'h010, 32'h0000_0001, 0);   // 只写 bit0=1
apb_read (12'h010, data, 0);
check(data[0] === 1'b0, "done_irq did not clear by W1C");
check(data[1] === 1'b1, "err_irq must hold when W1C writes 0 to its bit");
check(vif.irq_o === 1'b1, "irq_o must stay high while err_irq still set");

apb_write(12'h010, 32'h0000_0002, 0);   // 再清 bit1
check(data[1] === 1'b0, "err_irq did not clear by W1C");
check(vif.irq_o === 1'b0, "irq_o did not deassert after err_irq W1C");
```

RTL 的 RW1C 在 197-204 行：只看 `PWDATA[0]`/`[1]` 是否为 1，为 1 才清，写 0 不动。
所以只写 1 的时候，`err_irq_sta_r` 必须原地不动、`irq_o` 也不掉；两位都清掉才落 0。

**EN 门控（口述 5.3 的代码证据）**，搜 `[评分 1-选做5.3]`：把 `IRQ_EN` 写成
`2'b10`（关掉 done_en）再跑同样的坏包，`done` 照样发生但 `done_irq_sta_r` 必须保持 0 —
— 说明 EN 只门控"能不能置位"，不参与 `irq_o` 的或运算。

拉低 `PRESETn`，恢复后 `busy_o`/`done_o` 必须归 0，DONE 之后复位则 `RES_*` 归 0
（搜 `[附加证据`）。
