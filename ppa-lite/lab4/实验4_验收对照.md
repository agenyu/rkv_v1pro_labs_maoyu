## 1 一键回归（10 + 5 + 5 分）

```powershell
make regress
```

这条命令内部干了什么，按 `Makefile` 的目标顺序讲：

1. **编译**（`comp` 目标）：`vlib work`，DUT 用 `-cover sbceft` 编（六类覆盖率全开），
   TB 只用普通 `vlog` 编（不往 DUT 分母里掺 TB 代码）。
2. **双层循环**（`regress` 目标）：外层遍历 `REGRESS_TESTS`（14 个用例），
   内层遍历 `SEEDS`（默认 `1 2 3`），共 42 次。
3. **每次仿真**都带 `-coverage`，并在退出时落一个 ucdb：
   ```
   -do "coverage save -onexit cov/runs/<test>_<seed>.ucdb; run -all; quit -f"
   ```
   日志文件名按用例前缀自动落到对应实验目录：`lab1/logs/run_<test>_<seed>.log`。
4. **每次仿真后两道 grep**：必须同时有 `[TEST PASS]` 和 `Errors: 0, Warnings: 0`，
   否则 `exit 1`。这一步很关键——`quit -f` 会让进程退出码恒为 0，不 grep 的话
   用例挂了也会显示"回归通过"。
5. **合并**（`mergecov`）：`vcover merge` 把 42 个 ucdb 合成 `cov/merged.ucdb`，
   再按 `-instance /tb/dut -recursive` 裁出只含 DUT 的 `cov/dut_merged.ucdb`。
6. **过滤**（`filtercov`）：`cov_exclude.do` 把登记在册的不可达项排除，
   另存 `cov/dut_filtered.ucdb`。
7. **出报告**（`report`）：HTML 两份 + 文本四份。

Lab1-3 必做场景的分布（`Makefile` 顶部四个变量）：

| 变量 | 用例 | 对应实验 |
|---|---|---|
| `LAB1_TESTS` | `lab1_defaults_test` `lab1_pkt_mem_test` `lab1_pslverr_test` | 实验1 必做1/2/3 + 选做4 |
| `LAB2_TESTS` | `lab2_valid_test` `lab2_errors_test` | 实验2 必做1/2 + 选做4/5 |
| `LAB3_TESTS` | `lab3_e2e_test` `lab3_two_frames_test` `lab3_busy_protect_test` `lab3_irq_test` `lab3_reset_recovery_test` | 实验3 必做1/2/3 + 选做4/5 |
| `LAB4_TESTS` | `lab4_random_test` `lab4_error_mix_test` `lab4_closure_test` `lab4_code_cov_test` | 实验4 随机/交叉/闭合/补覆盖 |

## 2 五类覆盖率（15 + 5 分）

### 2.1 数字

原始（`cov/dut_merged.ucdb`）和过滤后（`cov/dut_filtered.ucdb`）的对照：

| 覆盖率类型 | 原始 | 过滤后 | 被排除的 bin |
|---|---|---|---|
| Branch 分支 | 101/103 = 98.05% | **101/101 = 100%** | FSM default 2 个 + if/else-if all-false 1 个 |
| Condition 条件 | 27/28 = 96.42% | **28/28 = 100%** | `busy_r=1` 组合 1 个 |
| Expression 表达式 | 35/35 = 100% | **35/35 = 100%** | — |
| FSM 状态 | 3/3 = 100% | **3/3 = 100%** | — |
| FSM 转移 | 5/5 = 100% | **5/5 = 100%** | — |
| Statement 语句 | 158/163 = 96.93% | **158/158 = 100%** | default 分支里 5 条赋值 |
| Toggle 翻转 | 1325/1329 = 99.69% | **1325/1325 = 100%** | PREADY 两处 1→0，共 4 个 bin |
| **综合** | **98.73%** | **100.00%** | 共 13 个 bin |

功能覆盖率 `cg_ppa` 一直是 24/24 = 100%，不受过滤影响。

**答辩时的标准说法**：过滤前 98.73%，缺口全部是结构性不可达（不是激励没写到）；
按登记表排除后五类全 100%。不要一上来就说 100%，先说原始数字再说过滤，
否则会被追问"是不是排出来的"。

## 4 覆盖率过滤合规（10 + 5 + 5 分）

### 4.1 登记表字段

`coverage_filter_register.xlsx`（和同内容的 `.csv`）：

| 列 | 含义 |
|---|---|
| `object` | 被排除的对象（实例路径 / 代码位置） |
| `object_type` | 类型：TB helper / Defensive RTL / Unreachable combination / Constant toggle |
| `location` | 具体文件和行号，**这就是"行数"** |
| `item_count` | 涉及的 bin 数 |
| `exclude_ref` | 对应 `cov_exclude.do` 的第几行，或 `vcover report -instance` |
| `reason` | 为什么不可达 |
| `conclusion` | 从分母里排除 / 保留并说明 |

### 4.2 登记表与配置一一对应（5 分）

`cov_exclude.do` 每条命令的注释都以 `CSV row N` 开头，登记表的 `exclude_ref`
反过来指回行号：

| CSV 行 | 对象 | 位置 | exclude_ref |
|---|---|---|---|
| 1 | `/tb/u_lab1_m1` | `tb/tb.sv:33-67` | `vcover report -instance /tb/dut` |
| 2 | `/tb/u_m3_standalone` | `tb/tb.sv:69-89` | 同上 |
| 3 | FSM default branch | `packet_proc_core.sv:230` | `cov_exclude.do` 里 `CSV row 3` |
| 4 | FSM default statements | `packet_proc_core.sv:231-236` | `CSV row 4` |
| 5 | 条件 `busy_r=1` | `packet_proc_core.sv:119` | `CSV row 5` |
| 6 | `u_m1` PREADY | `apb_slave_if.sv:77` | `CSV row 6` |
| 7 | 顶层 PREADY | `ppa_top.sv:74` | `CSV row 7` |
| 8 | if/else-if all-false | `packet_proc_core.sv:148` | `CSV row 8` |

抽查时打开 `cov_exclude.do` 搜 `CSV row N`，注释里写着同样的文件名行号，一眼能对上。

**注意前两行是"作用域排除"，不是 bin 排除**：它们靠 `vcover merge -instance /tb/dut`
实现（把 TB 里的 helper 实例挡在统计范围外），其余 6 条靠 `coverage exclude`。
两种机制都写进了 `exclude_ref` 列，答辩时要能区分。

## 7 波形（追问时用，不计分）

实验4 的评分项里没有"看波形"，但答辩被问到"某个 bin 为什么是 0""非法类型那一路信号怎么走的"时，
开波形比翻代码快。四个用例的 wlf 已经生成在 `lab4/wave_ppa/`：

```powershell
make wave4        # 重新生成四个 -> lab4/wave_ppa/*.wlf
# 日志在 lab4/logs/run_wave_lab4_*.log

vsim -view lab4/wave_ppa/lab4_random_test.wlf    -do wave/ppa_wave.do
vsim -view lab4/wave_ppa/lab4_error_mix_test.wlf -do wave/ppa_wave.do
vsim -view lab4/wave_ppa/lab4_closure_test.wlf   -do wave/ppa_wave.do
vsim -view lab4/wave_ppa/lab4_code_cov_test.wlf  -do wave/ppa_wave.do
```

`vsim -view` 会占住终端直到窗口关闭，四条不能连着敲。双击工程根目录的
`打开实验4波形.bat` 可以一次弹出四个窗口。

实验4 全部走主通路 `dut`（`ppa_top`），所以统一用 `wave/ppa_wave.do`，
不要用 `ppa_wave_lab1.do`（那是独立 M1）或 `ppa_wave_m3.do`（那是实验2 的 standalone M3），
用错会看到满屏 0。

几个常用看法：

| 追问 | 看哪个 wlf | 看什么信号 |
|---|---|---|
| 非法包怎么被拒 | `lab4_error_mix_test.wlf` | `dut/u_m3/state`、`length_error`/`type_error`/`chk_error` |
| 8 个字怎么进 SRAM | `lab4_code_cov_test.wlf` | `dut/u_m1/pkt_mem_we_o`、`dut/u_m2/mem[0..7]` |
| busy 期间写 CSR 被挡住 | `lab4_closure_test.wlf` | `dut/u_m1/busy_i` 与写入 `PSEL/PENABLE` |
| 地址译码边界 | `lab4_code_cov_test.wlf` | `dut/u_m1/PADDR` 与 `PSLVERR` |

`log` 里登记了 `dut/u_m2/mem` 数组，SRAM 8 个字的实时内容能直接在波形里展开。
