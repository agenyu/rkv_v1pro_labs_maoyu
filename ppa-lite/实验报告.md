| 实验 | 主要实现 |

| Lab1 | APB 3.0 从接口、CSR、PKT_MEM 窗口、SRAM、PSLVERR、IRQ |
| Lab2 | M3 三态 FSM、包头解析、长度/类型/校验检查、payload sum/xor |
| Lab3 | `ppa_top` 集成、端到端链路、连续帧、busy 保护、复位和中断闭环 |
| Lab4 | 统一回归、功能覆盖、五类代码覆盖、testplan、过滤登记 |

## 2 验证环境

验证环境由以下部分组成：

- `packet_item`：固定数组保存 8 个 SRAM word；动态数组保存实际 payload；
  队列组织 packet 字节；关联数组保存 case 名称到预期结果类型的映射；生成参考
  length/type/checksum、payload sum/xor 和错误结果。
- `coverage_collector`：covergroup 采样 length、type、result 和 algo mode。
- `base_test`：APB driver、M3 driver、参考结果检查、超时、APB transaction
  queue 和 PASS/FAIL 汇总。
- `apb_monitor` / `apb_scoreboard`：独立监视 APB 实际事务，经 mailbox 发送到
  独立 scoreboard；事件与 driver 结果相互独立。
- 13 个派生的 testcase：通过 `+TESTNAME=` 选择，未知名称直接 fatal。
- standalone M3 模型：Lab2 不依赖 M1 RTL。
- `mailbox`、`fork...join`、`fork...join_any`、timeout、semaphore 和 virtual
  task：用于并发回归、等待和 APB 访问互斥；后台 monitor 使用 `fork...join_none`。
- 日志打印 `[TEST START] <test> seed=<n>`、`[TEST PASS] <test>`，并检查工具
  退出统计为 0 error、0 warning。

## 5 覆盖率过滤与未覆盖项

本工程没有通过修改 DUT 源码、删除 testcase 或伪造功能 bin 来提高覆盖率。

代码覆盖率统计只保留 `/tb/dut` DUT 层次，测试平台中的 standalone M1
stub 和 standalone M3 模型不计入 DUT 分母。过滤对象、数量和原因已登记在
`coverage_filter_register.xlsx`。

剩余未覆盖项不影响达到正式“通过”门槛：

- 部分全零 PADDR 低位/高位：APB word 地址天然只访问 4-byte 对齐地址。
- `PREADY` 固定为 1：1→0 翻转在协议实现中不可达。
- 少量防御性 default 分支和内部循环变量：不是 PPA 功能状态。

五类 DUT 代码覆盖率均大于 90%；功能覆盖为 100%，断言/检查日志为 0 error。
